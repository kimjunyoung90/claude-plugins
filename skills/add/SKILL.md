description: 할 일 목록에 새 할 일을 추가하고 지라 티켓을 붙인다(없으면 승인 뒤 생성). "할 일 추가", "할 일에 넣어줘", "todo 추가", "/todo:add" 요청 시 사용. 세션 시작은 하지 않는다(그건 /start).
argument-hint: "<할 일 내용> [티켓 키]  — 여러 건이면 줄마다 하나"

대상: `$ARGUMENTS`. 비어 있으면 무엇을 추가할지 묻는다. 여러 줄이면 줄마다 한 건이다.
명령: `todo.py` = `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/todo.py"`. 할 일은 반드시 티켓과 함께 추가한다.

## 1. 내용 정리

건마다 아래를 정한다. 사용자가 말하지 않은 것은 지어내지 않는다.

- 제목: 무엇을 하는 일인지 한 줄로. 사용자가 쓴 말을 살리고, 티켓 키 표기는 제목에서 뺀다. 누가 맡겼는지는 적지 않는다 — 지라 티켓에 남긴다.
- 메모: 기한·배경처럼 제목에 다 담기 어려운 말이 있으면 메모로.
- 티켓: 지라 키(`<프로젝트>-<번호>`)를 말했으면 그 티켓을 쓴다. 없으면 새로 만들 내용을 정한다.

## 2. 중복 확인

`todo.py todo` 로 지금 할 일을 보고, 같은 일로 보이는 건이 있으면 추가하지 않고(티켓도 만들지 않고) 그 건의 번호와 함께 알린다. 애매하면 사용자에게 묻는다.

## 3. 새 티켓 준비

티켓 키가 없는 건만. 아직 만들지 않는다 — 지라에 남는 일이라 4단계 승인 뒤에 만든다.

- 프로젝트: `todo.py todo --all`(끝난 일 포함) 에서 비슷한 일에 붙은 티켓의 프로젝트를 따른다. 짐작이 안 서면 4단계에서 묻는다.
- 티켓 제목: 할 일 제목을 티켓 제목답게 다듬는다.
- 유형·담당자: 기본은 「작업」(없으면 Task)·나. 아래로 확인한다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/jira-create.py" <프로젝트> --summary "<티켓 제목>" --dry-run
```

## 4. 확인

추가할 건 전부를 한 번에 보여 주고 승인을 받는다. 기존 티켓만 쓰는 건뿐이면 묻지 않고 5단계로 간다.

```
1. <할 일 제목>
   티켓: <KEY> (기존) | 새로 만듦 — <프로젝트> 「<유형>」 <티켓 제목>
```

## 5. 티켓 생성 · 추가

승인한 새 티켓부터 만든다. 마지막 줄 `생성: <KEY>` 의 키로 할 일을 추가한다. 티켓 생성이 실패하면 그 건은 추가하지 않고 메시지를 그대로 전한다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/jira-create.py" <프로젝트> --summary "<티켓 제목>" [--type <유형>]
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/todo.py" add --title "<제목>" --jira <KEY> [--note "<메모>"]
```

**완료 기준**: 건마다 할 일 id·티켓·`todo.py todo` 에서의 번호를 한 줄씩 알린다. 바로 시작하려면 `/start <번호>` 를 쓴다고 덧붙인다.
