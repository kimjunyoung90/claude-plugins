대화 중에 드러난 "몰랐던 것"을 학습 로그에 남겨 복습 대상으로 만든다. 복습(`review` 스킬)은 학습 로그를 읽어 복습 문제를 내므로, 여기서 남긴 행이 다음 복습 시험의 재료가 된다.

# 경로와 형식
경로 설정, 학습 로그의 표 형식(12개 열, 원인 분류, 단계), 행을 고치는 방법은 **`<SKILL>/../../references/learning-log-format.md`** 를 따른다(`<SKILL>`은 이 스킬의 기본 폴더). 기록하기 전에 읽는다.
- **설정 파일이 없으면** 기록하지 말고 `/genius:setup`을 먼저 실행하라고 한 줄로 안내한다. 질문에는 그대로 답한다.

# 기록할 질문인가
기준은 하나다. **답을 듣고 나서 자기 말로 설명할 수 있어야 하는 것은 기록하고, 다시 찾아보면 끝나는 것은 기록하지 않는다.** 시험이나 공부 중인지는 따지지 않는다. 다른 일을 하다가 나온 질문도 기준에 맞으면 기록한다.

| 기록함 | 기록 안 함 |
|---|---|
| "TLS에서 key_share가 뭐야?" (원리를 모름) | "git rebase 옵션 뭐였지?" (도구 사용법) |
| "RSS랑 VSZ 차이가 뭐야?" (비슷한 개념이 헷갈림) | "genius.json 어디 있어?" (경로·설정) |
| "인덱스 걸었는데 왜 풀스캔하지?" (알던 개념을 상황에 못 씀) | "grade가 스킬이야?" (스킬 사용법) |
| "아 TIME은 켜진 시간이구나" (틀린 이해, 3번으로) | "HTTP 상태 코드 418이 뭐더라" (찾아보면 끝나는 사실) |

# 무엇을 기록하나

## 1. 개념 질문
위 기준에 맞는 질문. 시험 해설을 읽다가 한 질문, 오답노트 검토 중 질문, 공부와 상관없는 작업 중 질문 모두 포함한다.
- 한 질문당 한 행: `문제` `(질문) 질문 내용`, `몰랐던 것` 주제만, `내 답` `-`, `결과`와 `유형` `질문`, `원인` `개념 공백`, `단계` 1, `다음 복습일` 질문한 날 + 1일, `이력` `MM-DD 질문`.
- **이미 같은 개념의 행이 있으면** 새 행을 만들지 않고 그 행의 `이력`에 `MM-DD 질문(질문 요지)`를 덧붙인다. 같은 개념인지는 `몰랐던 것`과 `문제`로 판단한다. 시험 문항 행도 포함해서 찾는다.

## 2. 자기 말 요약
사용자가 답을 듣고 "아 ~구나", "그럼 ~라는 거지?"처럼 자기 말로 정리하면, 그 개념의 행 `내 한 줄`에 원문 그대로 덧붙인다.
- 요약이 맞으면 그대로 적는다.
- 요약에 틀린 부분이 있으면 아래 3번으로 처리한다.

## 3. 이해 확인 (틀린 이해)
사용자의 이해나 요약에 틀린 부분이 드러나면 오개념이므로 새 행으로 남긴다: `문제` `(이해 확인) ...`, `내 답`에 사용자 문장 원문, `결과` `틀림`(일부만 틀리면 `일부 틀림`), `원인` `오개념`, `유형` `이해 확인`, `단계` 1, 다음 복습일 다음 날.
- 맞은 이해는 새 행을 만들지 않는다(2번처럼 `내 한 줄`에만 남긴다).
- 이미 있는 행의 오개념이 다시 드러난 것이면 원인을 갱신하고 `이력`에 덧붙인다(예: `개념 공백` → `오개념`).

## 4. 답 요지 기록
질문 행과 이해 확인 행은 정답 키가 없으므로, 답의 요지를 `<KEYS>/질문 기록.md`에 남긴다. 복습 시험(`review` 스킬)이 이것을 출제와 채점의 근거로 쓴다. 노트를 정리하지 않은 질문도 이것으로 복습할 수 있다.
- 학습 로그 행마다 `## 날짜 · [[노트]] · 문제` 제목 하나(학습 로그 행의 칸 값 그대로). 이미 있으면 그 아래에 덧붙인다.
- 항목 한 줄: `- MM-DD 질문 요지: 답 요지`. 실제 명령으로 확인했으면 끝에 `근거: 명령(본 값)`을 붙인다.
- 답 요지는 Claude가 설명한 핵심을 1~3문장으로. 사용자 문장은 여기가 아니라 학습 로그 `내 한 줄`에 둔다.
- 설명이 노트와 다르거나 확신이 없으면 그렇다고 적는다(복습 채점에서 단정하지 않게).

# 마무리
- 기록했으면 응답 끝에 "학습 로그에 기록했다"고 한 줄로, 무엇을 어느 행에 했는지 짧게 알린다.
- 질문 내용이 노트에 없으면 노트 보강을 제안한다. 고치는 것은 사용자가 원할 때 한다.
- 시험 중(문제를 풀고 있는 중)에는 개념을 설명하지 않는다. 설명은 사용자가 시험을 멈추고 요청할 때 한다.
