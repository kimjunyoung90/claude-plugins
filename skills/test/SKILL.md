공부한 개념을 **인출 연습**으로 굳히는 시험 스킬이다. 노트를 다시 읽게 하지 않고, 기억에서 꺼내 답하게 한다.

# 경로와 공용 규칙
`<SKILL>`은 이 스킬의 기본 폴더, `<ROOT>`는 플러그인 루트(`<SKILL>/../..`)다.
- 경로: `<NOTES>`는 `${user_config.notes_path}`, `<GENIUS>`는 `${user_config.genius_path}`다. 셸에서는 공백이 있을 수 있으므로 항상 따옴표로 감싼다. 폴더나 파일이 없으면 만든다.
- 학습 로그 형식: `<ROOT>/references/learning-log-format.md`
- 출제 원칙: `<ROOT>/references/exam-questions.md`
- 시험지 경로·형식·PDF 변환: `<ROOT>/references/exam-sheet.md`
- 대화형 채점: `<ROOT>/references/grading.md`

# 1. 입력 해석
- **기본은 항상 손글씨로 푸는 PDF 시험지다.** `/genius:test`를 실행하면 묻지 말고 시험지를 만든다(3번). 기기(아이패드 등)는 가정하지 않는다.
- 인자가 노트 이름이나 경로면 그 노트로 시험지를 만든다. `<NOTES>`에서 이름으로 찾고(`find`), 일치하는 파일이 여러 개면 목록을 보여 주고 고르게 한다. 끝의 `pdf`는 붙어 있어도 무시한다(예전 문법).
- 인자가 없으면 묻지 않고 노트를 정해 시험지를 만든다. 순서: ① 이 대화에서 공부한 노트 ② 학습 로그에서 가장 최근 날짜 행의 노트. 둘 다 없을 때만 어떤 노트로 볼지 묻는다. 시작 메시지에 고른 노트를 한 줄로 알린다.
- 인자 끝에 `chat`이 붙었을 때만(`/genius:test <노트> chat`) **대화형 시험**(4번)으로 한 문제씩 진행한다.
- 인자에 `pre`가 붙으면(`/genius:test <노트> pre`) **사전 테스트**(5번)로 진행한다.
- 예전 문법(`/genius:test grade`, `check`, `review`)이 들어오면 각각 `/genius:grade`, `/genius:note`, `/genius:review`로 바뀌었다고 한 줄로 알리고 그 스킬을 따른다.

# 2. 시작
- 노트를 읽되 **내용을 사용자에게 보여 주지 않는다.**
- 시작 메시지에는 대상 노트 이름, 문제 수, 진행 방식(노트 보지 않고 풀기)만 짧게 알린다.
- 같은 대화에서 방금 그 개념을 공부했다면 "하루 뒤에 풀면 더 정확하다"고 한 줄만 안내하고, 시험지는 그대로 만든다.
- 사용자가 아직 그 노트를 읽지 않았다고 했거나, Claude가 새로 쓰거나 크게 보강했는데 사용자가 읽지 않은 노트라면 묻지 않고 **사전 테스트**(5번)로 만들고 그렇게 했다고 한 줄로 알린다. 읽지 않은 내용으로 본 시험을 복습 시험처럼 채점하면 "모르는 것"과 "잊은 것"이 학습 로그에 섞인다.

# 3. 시험지 만들기
1. 출제 원칙에 따라 노트를 읽고 문제를 만든다. 시험지에 **정답이나 힌트를 넣지 않는다.**
2. 답안지를 저장한다(경로는 `exam-sheet.md`, 내용은 `exam-questions.md`의 "답안지").
3. `exam-sheet.md`의 형식으로 시험지 HTML을 만들고 PDF로 변환해 확인한다.
4. 사용자에게 파일 위치(`<GENIUS>/시험`)만 짧게 알리고, 다 풀면 `/genius:grade`를 하도록 안내한다.

# 4. 대화형 시험 (`chat`)
- **한 번에 한 문제**만 낸다. 사용자가 답하면 `grading.md`에 따라 채점하고 다음 문제로 간다.
- 정답이나 힌트를 미리 보여 주지 않는다.
- 사용자가 "모르겠다"고 하면 힌트를 한 단계만 주고 다시 답하게 한다. 그래도 모르면 정답을 알려 주고 **오답으로 처리**한다.
- 끝나면 `grading.md`의 결과 요약과 학습 로그 기록을 한다.

# 5. 사전 테스트 (`pre`)
아직 읽지 않은 노트로 미리 시험을 본다. 틀려도 정답을 바로 공부하면 그냥 읽는 것보다 학습이 잘 된다. 목적이 "측정"이 아니라 "뒤에 읽을 내용에 대한 질문 만들기"이므로 본 시험과 다르게 다룬다.

1. 문제는 3~5개, 노트의 **핵심 개념**만 묻는다. 세부 사항이나 여러 개념을 엮은 문항은 내지 않는다.
2. 진행과 채점은 대화형 시험과 같다. 다만 "모르겠다"는 바로 받아들이고 정답과 피드백으로 넘어간다(힌트 단계 생략). 틀려도 괜찮다고 시작할 때 한 줄로 알린다.
3. 결과 요약에 점수를 크게 강조하지 않는다. 대신 "노트를 읽을 때 특히 볼 부분"을 문항별로 짚는다.
4. **학습 로그에 기록하지 않는다.**
5. 마무리로 지금 노트를 읽으라고 안내하고, 하루 이상 지난 뒤 `/genius:test <노트>`로 본 시험을 보라고 권한다.
6. PDF로 만들면 시험지 제목을 `사전 테스트: 노트이름`으로 하고, 답안지 파일 이름 끝에 ` (사전)`을 붙인다.

# 주의
- 응답은 한국어로 하고, 부연 설명에 em-dash(—)를 쓰지 않는다. 괄호나 줄 분리를 쓴다.
- 쓰기는 `<GENIUS>/.답안지/`(답안지), `<GENIUS>/시험/`(시험지), `<GENIUS>/학습 로그.md`(대화형 시험)에만 한다. 시험 대상 노트가 틀린 것 같으면 알리기만 하고, 고치는 것은 사용자가 요청할 때 한다.
- 시험 중에는 노트 내용을 요약하거나 다시 설명해 주지 않는다. 사용자가 시험을 중단하고 설명을 요청하면 그때 응한다.
