공부 중에 드러난 "몰랐던 것"을 학습 로그에 남겨 복습 대상으로 만든다. 시험(`test` 스킬)은 학습 로그를 읽어 복습 문제를 내므로, 여기서 남긴 행이 다음 복습 시험의 재료가 된다.

# 경로 설정
경로는 PC마다 다르므로 스킬에 직접 쓰지 않고 **`~/.claude/study-kit.json`** 에서 읽는다. `test` 스킬도 같은 파일을 쓴다.

```json
{
  "notes_dir": "공부 노트(마크다운) 폴더. 예: Obsidian vault",
  "study_dir": "학습 로그와 시험지 PDF를 두는 폴더. 여러 기기에서 열 수 있는 동기화 폴더 권장",
  "answer_key_dir": "정답 키 폴더. 시험 전에 눈에 띄지 않게 숨김 폴더 권장"
}
```

- 아래에서 `<NOTES>`, `<STUDY>`, `<KEYS>`는 각각 `notes_dir`, `study_dir`, `answer_key_dir`를 뜻한다. `~`는 `$HOME`으로 풀고, 경로에 공백이 있을 수 있으므로 셸에서는 항상 따옴표로 감싼다.
- 학습 로그: `<STUDY>/학습 로그.md`
- **설정 파일이 없으면** 세 경로를 사용자에게 한 번에 물어 만든다. 폴더가 없으면 만들지 물어본다. 묻기 전에 흔한 위치(iCloud Drive, Obsidian vault)가 있는지 찾아 보고 후보로 제시한다.

# 표 형식
`<STUDY>/학습 로그.md`가 없으면 아래 헤더로 만든다. 열은 12개다.

```markdown
# 학습 로그

| 날짜 | 노트 | 문제 | 몰랐던 것 | 내 답 | 결과 | 원인 | 내 한 줄 | 이력 | 유형 | 단계 | 다음 복습일 |
|---|---|---|---|---|---|---|---|---|---|---|---|
```

- **표에 정답이나 AI 해설을 적지 않는다.** 표를 열어 보는 순간 복습이 다시 읽기가 되기 때문이다. 정답과 해설은 정답 키 파일(`<KEYS>/`)에만 둔다.
- `노트`: `[[노트 이름]]` 위키링크.
- `몰랐던 것`: 무엇을 몰랐는지 **주제만** 적는다(예: `ps aux의 TIME 칸이 뜻하는 것` ○, `TIME은 누적 CPU 시간` ✗). 확신 정답은 `-`.
- `내 답`: 사용자 답을 요약하지 말고 원문 그대로(길면 앞부분만) 적는다. 질문 행은 `-`.
- `원인`: 확신 정답은 비운다. 나머지는 `개념 공백`(모름) / `오개념`(확신하고 틀림) / `혼동`(비슷한 개념과 섞음) / `적용 실패`(개념은 알지만 상황에 못 씀) / `표현 부족`(방향은 맞으나 핵심 누락) / `단순 사실` / `참고함` 중 하나.
- `내 한 줄`: 사용자가 자기 말로 정리한 문장을 **원문 그대로** 적는다. 고쳐 쓰지 않는다. 여러 번 생기면 ` / `로 이어 붙인다. 없으면 `-`.
- `이력`: `MM-DD 결과`를 ` → `로 이어 붙인다(예: `10-08 오답 → 10-09 부분 → 10-13 질문`). 덮어쓰지 않는다.
- `단계`: 1(1일 뒤), 2(3일 뒤), 3(7일 뒤), 4(14일 뒤), 5(30일 뒤), 졸업. 시험 결과에 따른 시작 단계와 복습 결과에 따른 갱신은 `test` 스킬이 정한다.

# 무엇을 기록하나

## 1. 개념 질문
사용자가 공부 주제의 개념을 **몰라서** 한 질문. 시험 해설을 읽다가 한 질문, 오답노트 검토 중 질문, 일반 대화 중 질문 모두 포함한다.
- 기록하지 않는 것: 도구 사용법, 경로, 스킬·설정 사용법, 약어의 이름처럼 찾아보면 되는 사실만 묻는 질문.
- 한 질문당 한 행: `문제` `(질문) 질문 내용`, `몰랐던 것` 주제만, `내 답` `-`, `결과`와 `유형` `질문`, `원인` `개념 공백`, `단계` 1, `다음 복습일` 질문한 날 + 1일, `이력` `MM-DD 질문`.
- **이미 같은 개념의 행이 있으면** 새 행을 만들지 않고 그 행의 `이력`에 `MM-DD 질문(질문 요지)`를 덧붙인다. 같은 개념인지는 `몰랐던 것`과 `문제`로 판단한다. 시험 문항 행도 포함해서 찾는다.

## 2. 자기 말 요약
사용자가 답을 듣고 "아 ~구나", "그럼 ~라는 거지?"처럼 자기 말로 정리하면, 그 개념의 행 `내 한 줄`에 원문 그대로 덧붙인다.
- 요약이 맞으면 그대로 적는다.
- 요약에 틀린 부분이 있으면 아래 3번으로 처리한다.

## 3. 이해 확인 (틀린 이해)
사용자의 이해나 요약에 틀린 부분이 드러나면 오개념이므로 새 행으로 남긴다: `문제` `(이해 확인) ...`, `내 답`에 사용자 문장 원문, `결과` `틀림`(일부만 틀리면 `일부 틀림`), `원인` `오개념`, `유형` `이해 확인`, `단계` 1, 다음 복습일 다음 날.
- 맞은 이해는 새 행을 만들지 않는다(2번처럼 `내 한 줄`에만 남긴다).
- 이미 있는 행의 오개념이 다시 드러난 것이면 원인을 갱신하고 `이력`에 덧붙인다(예: `개념 공백` → `오개념`).

# 쓰는 방법
- 학습 로그 경로는 위 "경로 설정"에서 정한다. 노트를 찾을 때는 `<NOTES>`에서 `find`로 찾는다.
- 수정 전에 학습 로그를 스크래치패드에 백업한다.
- 행은 Python으로 고친다. 칸을 고칠 때는 `|`로 나눈 뒤 해당 칸만 바꾸고, 바꿀 행이 정확히 하나인지 확인한다(`assert`).
- 고친 뒤 모든 표 행의 열이 12개인지 확인한다.
- 새 행은 같은 노트의 행들 근처(같은 노트의 마지막 행 뒤)에 넣는다. 찾기 어려우면 표 끝에 붙인다.

# 마무리
- 기록했으면 응답 끝에 "학습 로그에 기록했다"고 한 줄로, 무엇을 어느 행에 했는지 짧게 알린다.
- 질문 내용이 노트에 없으면 노트 보강을 제안한다. 고치는 것은 사용자가 원할 때 한다.
- 시험 중(문제를 풀고 있는 중)에는 개념을 설명하지 않는다. 설명은 사용자가 시험을 멈추고 요청할 때 한다.
