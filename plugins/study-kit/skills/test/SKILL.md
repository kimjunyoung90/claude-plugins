공부한 개념을 **인출 연습**으로 굳히는 시험 스킬이다. 노트를 다시 읽게 하지 않고, 기억에서 꺼내 답하게 한다.

# 경로
- 경로는 **`~/.claude/study-kit.json`** 에서 읽는다(형식과 없을 때 만드는 방법은 `study-log` 스킬의 "경로 설정"). `<NOTES>` 노트 폴더, `<STUDY>` 학습 폴더, `<KEYS>` 정답 키 폴더. `~`는 `$HOME`으로 풀고 경로는 항상 따옴표로 감싼다.
- 학습 로그: `<STUDY>/학습 로그.md`
- `<STUDY>` 하위 폴더: `시험`(시험지, 답안), `복습`(복습 시험지, 복습 채점 시험지), `오답`(오답노트 PDF, 복습 오답노트 포함). 없으면 만든다.
- 스크립트는 이 스킬 폴더의 `scripts/`에 있다(`<SKILL>`은 이 스킬의 기본 폴더). PDF 변환과 필기 자르기는 macOS의 Swift(WebKit, PDFKit)를 쓰므로 **macOS에서만 동작한다.**
- 노트 앱 전용 폴더(GoodNotes 등)에는 시험지를 넣지 않는다. 앱이 자체 저장소(CloudKit 등)를 써서 그 폴더에 PDF를 넣어도 앱에 뜨지 않는다. 시험지는 `<STUDY>`에 두고 사용자가 원하는 앱으로 연다.

# Step 0. 입력 해석
- **기본은 항상 손글씨로 푸는 PDF 시험지다.** `/test`를 실행하면 묻지 말고 시험지를 만든다(Step 7-A). 기기(아이패드 등)는 가정하지 않는다.
- 인자가 노트 이름이나 경로면 그 노트로 시험지를 만든다. `<NOTES>`에서 이름으로 찾고(`find`), 일치하는 파일이 여러 개면 목록을 보여 주고 고르게 한다. 끝의 `pdf`는 붙어 있어도 무시한다(예전 문법).
- 인자 끝에 `chat`이 붙었을 때만(`/test <노트> chat`) **대화형 시험 모드**로 한 문제씩 진행한다.
- 인자가 `grade`면 **PDF 채점 모드**로 진행한다. Step 7-B로 간다. 경로가 없으면 `<STUDY>/시험`과 `<STUDY>/복습`을 함께 보고 가장 최근에 수정된 `... 시험지.pdf`(또는 `... 답안.pdf`)를 쓴다.
- 인자가 `check`면 **해설 확인 모드**로 진행한다. Step 7-C로 간다. 경로가 없으면 `<STUDY>/시험`과 `<STUDY>/복습`을 함께 보고 가장 최근에 수정된 채점 시험지(제목이 `채점:`)를 쓴다.
- 인자가 `review`면 **복습 모드**로 진행한다. Step 6으로 간다.
- 하루 흐름: 시험지 풀기 → `/test grade`(채점, 문제마다 아래에 해설과 "질문·내 이해" 칸을 넣은 채점 시험지로 교체, 오답노트 PDF 생성, 학습 로그 기록) → 해설을 읽으며 모르는 표현과 내가 이해한 것을 칸에 필기 → `/test check`(질문에 답하고 이해가 맞는지 검토) → 시험지를 **닫은 뒤** 오답노트에 자기 말로 정리 → 복습일에 `/test review`(오답노트 필기를 학습 로그에 옮기고 복습 문제 출제)
- 인자에 `pre`가 붙으면(`/test <노트> pre`) **사전 테스트 모드**로 진행한다. Step 8을 따른다.
- 인자가 없으면 묻지 않고 노트를 정해 시험지를 만든다. 순서: ① 이 대화에서 공부한 노트 ② 학습 로그에서 가장 최근 날짜 행의 노트. 둘 다 없을 때만 어떤 노트로 볼지 묻는다. 시작 메시지에 고른 노트를 한 줄로 알린다.

# Step 1. 시작
- 노트를 읽되 **내용을 사용자에게 보여 주지 않는다.**
- 시작 메시지에는 대상 노트 이름, 문제 수, 진행 방식(노트 보지 않고 풀기)만 짧게 알린다.
- 같은 대화에서 방금 그 개념을 공부했다면 "하루 뒤에 풀면 더 정확하다"고 한 줄만 안내하고, 시험지는 그대로 만든다.
- 사용자가 아직 그 노트를 읽지 않았다고 했거나, Claude가 새로 쓰거나 크게 보강했는데 사용자가 읽지 않은 노트라면 묻지 않고 **사전 테스트 모드**(Step 8)로 만들고 그렇게 했다고 한 줄로 알린다. 읽지 않은 내용으로 본 시험을 복습 시험처럼 채점하면 "모르는 것"과 "잊은 것"이 학습 로그에 섞인다.

# Step 2. 출제 원칙
- **공부 목적은 실무에서 직접 다루는 능력과 전문가 수준의 소양이다(면접 대비 아님).** 개념을 말로 설명하는 것보다, 실제 화면(명령어 출력, 로그, 설정)을 읽고 판단하고 근거를 대는 능력을 본다.
- **문제 수는 개념 수에 맞춘다(보통 10~15문제).** 노트의 핵심 개념(소제목, 단계, 비교 대상)마다 한 문제를 낸다. 학습 로그의 질문·이해 확인 행은 **같은 개념끼리 묶어** 한 문제로 다룬다(예: MAC과 서명 관련 행 네 개 → 한 문제). 같은 개념을 각도만 바꿔 여러 번 묻지 않는다. 개념을 빼서 개수를 맞추지도 않는다. 쉬운 것부터 어려운 것 순서로 낸다.
- **실물 읽기와 실무 판단을 합쳐 절반 이상**으로 한다. 나머지는 예측하기, 오류 찾기 위주로 하고, 설명하기와 비교하기는 꼭 필요할 때만 낸다.

| 유형 | 예 |
|---|---|
| 설명하기 | "X는 무엇이고 왜 필요한가?" |
| 예측하기 | "이 상황에서 무슨 일이 생기나? 왜?" |
| 오류 찾기 | 일부러 틀린 문장을 주고 어디가 틀렸는지 묻기 |
| 상황 적용 | 노트의 개념 여러 개를 조합해야 풀리는 시나리오 |
| 비교하기 | 헷갈리는 두 개념의 차이 |
| 실물 읽기 | 명령어 출력, 로그, 패킷 캡처, 설정 파일, 에러 메시지를 주고 "여기서 무엇을 알 수 있나, 무엇이 문제인가"를 묻기 |
| 실무 판단 | 정답이 하나가 아닌 운영·설계 결정(트레이드오프, 장애 대응 순서). 선택보다 **근거**로 채점한다 |

- **실물 읽기 문제의 출력은 지어내지 않는다.** 로컬에서 실제로 실행해 얻은 출력(`openssl s_client`, `curl -v`, `dig`, `ps`, `ss` 등)을 필요한 부분만 잘라 쓴다. 실행할 수 없는 환경의 출력(장애 상황 로그 등)을 만들어야 하면 실제 형식을 따르고, 정답 키에 "구성한 예시"라고 적는다. 출력에서 정답을 그대로 읽을 수 있는 줄은 남기되, 무엇을 봐야 하는지는 문제에 쓰지 않는다.

- 노트의 개념을 **응용하면 풀 수 있는 문제**는 노트에 직접 적혀 있지 않아도 낸다. 실무자라면 알아야 할 도구 사용과 표준 동작(노트 개념에서 바로 이어지는 것)도 낼 수 있다. 단, 노트 개념과 상관없이 따로 외워야만 풀 수 있는 지식은 묻지 않는다. 이런 지식이 필요하면 문제에 출력이나 자료로 주고, 그것을 해석하게 한다.
- 노트 문장을 그대로 옮긴 문제를 내지 않는다. 표현을 바꿔서 물어 문장 암기로 통과하지 못하게 한다.
- 정답이 문제 안에 힌트로 드러나지 않게 한다.

## 무엇을 물을지 (출제 관점)
노트의 핵심 개념마다 아래 관점 중 맞는 것을 골라 문제를 만든다. 한 시험지 안에서 다섯 관점이 고루 나오게 한다. 유형(위 표)은 묻는 형식이고, 관점은 개념의 어느 면을 건드릴지 정하는 내용이다.

| 관점 | 묻는 것 |
|---|---|
| 1. 조건이 바뀌면 무엇이 깨지나 | 전제가 무너지거나 장애·공격·부하가 생기면, 무엇은 여전히 보장되고 무엇이 깨지나 |
| 2. 이 부품은 왜 있나 | 구성 요소 하나를 없애거나 바꾸면 무슨 일이 생기나 |
| 3. 실무 상황 | 운영·디버깅·설계 장면에 개념을 적용하기 |
| 4. 한계 | 이 개념이 보장하지 않는 것은 무엇인가 |
| 5. 흔한 오해 | 그럴듯하게 틀린 문장을 오류 찾기로 (학습 로그의 오개념을 우선) |

- 이름, 약어, 설정값처럼 찾아보면 되는 사실은 묻지 않는다. 이유를 알면 따라오는 사실은 이유를 묻는 문제로 대신한다.
- 관점은 출제용이다. 시험지에는 표시하지 않는다. 정답 키에는 문항마다 유형과 함께 적는다.

## 난이도 기준점
공개된 유명 대학 시험(예: Berkeley CS161, MIT 6.5660, Stanford CS155)의 문제 수준과 문체, 그리고 현업 장애 회고(postmortem)·운영 문서에 나오는 판단 장면을 기준으로 삼는다.
- 상황을 짧게 주고, 개념을 써서 판단하게 한다.
- 어려움은 지식의 양이 아니라 개념을 엮고 실물에 적용하는 데서 나오게 한다.

## 실습 과제
시험지 맨 끝에 **실습 과제 1~2개**를 붙인다. 문제로 묻기보다 직접 해 봐야 남는 것(예: `openssl`로 사설 CA를 만들어 신뢰 저장소 차이 재현하기, `curl -v`로 핸드셰이크 관찰하기)을 고른다.
- 사용자 환경(macOS 기준)에서 바로 실행 가능한 명령으로 단계를 적고, "관찰할 것"을 질문 형태로 1~2개 둔다. 결과는 답안칸에 적게 한다.
- 실습 과제는 점수에 넣지 않는다. 채점 때 관찰 결과가 개념과 맞는지만 짚고, 틀린 해석이 있으면 학습 로그에 `(이해 확인)` 행으로 남긴다.
- 실행 전에 시스템을 바꾸는 단계(신뢰 저장소에 인증서 추가 등)는 되돌리는 명령도 함께 적는다.

# Step 3. 진행
- **한 번에 한 문제**만 낸다. 사용자가 답하면 채점하고 다음 문제로 간다.
- 정답이나 힌트를 미리 보여 주지 않는다.
- 사용자가 "모르겠다"고 하면 힌트를 한 단계만 주고 다시 답하게 한다. 그래도 모르면 정답을 알려 주고 **오답으로 처리**한다.

# Step 4. 채점
- 판정은 **정답, 부분 정답, 오답** 셋 중 하나로 한다.
- **모든 문항에 피드백(해설)을 준다. 맞힌 문항도 빼지 않는다.** 판정 라벨만 주면 테스트 효과의 절반이 사라진다(피드백 유무 g 0.73 대 0.39). 채점 때 모든 문항의 해설을 바로 공개한다.
- 문항마다 해설에 넣을 것:
  - **판정**과 **내 답 요약**
  - **모범 답안 요점**: 핵심만 한두 줄
  - **내 답과의 차이**: 부분 정답은 빠진 요소나 연결을, 오답은 어떤 오개념이었는지를 짚는다
  - **왜 그렇게 생각하기 쉬운지**(헷갈림 문항): 그 오답이 그럴듯해 보이는 이유
  - **노트에서 볼 곳**(모름 문항)
  - 확신 정답은 답에 없던 연결 한 가지만 덧붙인다

| 문항 종류 | 판단 기준 | 오답노트 PDF |
|---|---|---|
| 확신 정답 | 표시 없이 맞힘 | 넣지 않음 |
| 헷갈림 | 답을 썼는데 틀림, 부분 정답, `?` 정답 | "오해형" 빈칸 |
| 모름 | "모름", 빈칸, 답이 사실상 없음 | "재구성형" 빈칸 |
| 단순 사실 | 이유를 설명할 수 없는 규칙(포트 번호, 컬럼 이름, 값의 대소 방향 등) | 넣지 않음. 복습에서 다시 맞히기로만 관리 |

- **모름이 문항의 절반 이상이면** 노트를 아직 읽지 않은 상태로 본다. 사전 테스트(Step 8)로 처리해 학습 로그에 기록하지 않고, 오답노트도 만들지 않는다. 모든 문항의 해설을 공개하고 노트를 읽은 뒤 다음 날 다시 시험 보라고 안내한다.
- 대화형 모드에서는 오답노트 PDF 대신, 해설을 보여 준 뒤 "해설을 닫고 자기 말로 정리해 보라"고 한 줄을 요청해 학습 로그 `내 한 줄`에 그대로 적는다.
- 사용자 답이 노트와 다르지만 타당해 보이면 단정하지 않는다. "노트가 틀렸거나 표현이 다른 것일 수 있다"고 표시하고 공식 문서 확인을 권한다.
- **확신이 없는 채점은 확신이 없다고 밝힌다.** 채점자인 Claude도 틀릴 수 있다. 사용자가 판정에 이의를 제기하면 근거를 다시 보고 판정을 바꿀 수 있다.
- 피드백은 위 항목 안에서 끝낸다. 노트 전체를 다시 강의하지 않는다.

## 답안 표시 처리
사용자가 답 옆에 남기는 표시는 다음과 같이 처리한다. (PDF 답안의 필기, 대화형 답변 모두 해당)

| 표시 | 뜻 | 처리 |
|---|---|---|
| `?` | 확신 없이 쓴 답 | 판정은 그대로 내리되, **정답이어도 일정상 부분 정답으로 처리**한다(확신 없이 맞힌 답은 피드백과 재출제가 없으면 사라지기 쉽다). 결과 칸에 `정답(확신 낮음)`처럼 적고, 결과 요약에 "우연 가능성 있는 정답"으로 따로 언급한다. |
| `(참고함)` | 노트나 자료를 찾아보고 쓴 답 | 판정은 그대로 내리되 **점수에는 정답으로 세지 않고** 결과 요약에 `참고함 N개`로 따로 표기한다. 판정과 무관하게 학습 로그에 기록하고 원인 칸에 `참고함`으로 적는다. |
| 표시 없음 + 오답 | 확신하고 틀린 답 | 오개념일 가능성이 높다. 원인 칸에 `오개념`으로 적는다. 피드백 직후에는 잘 고쳐지지만 1주 뒤에는 절반 가까이 되돌아가므로, 복습 모드에서 반드시 다른 각도로 다시 낸다. ("모름"이나 빈칸은 확신 오답이 아니라 `개념 공백`이다) |

- 두 표시가 함께 있으면 `(참고함)` 처리를 따른다.
- 확신 표시는 **채점 결과를 보기 전에** 남긴 것만 인정한다. 채점을 보고 나서 붙인 `?`는 반영하지 않는다.
- 표시가 없는데 답이 노트 문장과 지나치게 똑같으면(찾아본 것으로 보이면) 단정하지 말고 "찾아보고 쓰신 건가요?"라고 한 번만 확인한다.
- 사용자가 채점 중에 "이 문제는 찾아봤다"고 말하면 그 문제를 소급해서 `(참고함)`으로 처리한다.

# Step 5. 마무리와 오답 기록
시험이 끝나면 한 번에 정리한다. 문제마다 파일을 쓰지 않는다.

**결과 요약**
- 점수(정답 / 전체), 유형별 결과
- 약한 개념 1~2줄
- 다음 복습일

**학습 로그 기록**: **맞힌 문항을 포함해 모든 문항을 기록한다.** 한 번 맞힌 개념도 다시 꺼내지 않으면 한 달 뒤 절반 이상 잊힌다. 표 형식과 칸 규칙(몰랐던 것, 내 답, 원인, 내 한 줄, 이력, 단계)은 **`study-log` 스킬**(`~/.claude/skills/study-log/SKILL.md`)을 따른다. 시험에만 해당하는 규칙은 아래와 같다.

- `내 한 줄`: 오답노트가 있는 문항은 `grade` 때 `(정리 전)`으로 두고, 다음 `review` 때 오답노트 PDF의 필기를 읽어 원문 그대로 채운다. 오답노트가 없는 문항(확신 정답, 단순 사실)은 `-`.
- 시험 결과에 따른 시작 단계:

| 결과 | 시작 단계 | 다음 복습일 |
|---|---|---|
| 정답(확신) | 3 | 시험일 + 7일 |
| 정답(`?`), 부분 정답 | 1 | 시험일 + 1일 |
| 오답, `(참고함)` | 1 | 시험일 + 1일 |

- 정답(확신)도 3단계에서 시작하므로 졸업까지 서로 다른 날 세 번 더 맞혀야 한다.

시험 밖의 개념 질문, 자기 말 요약, 틀린 이해 기록은 `study-log` 스킬이 맡는다. 시험 대화 중에 나와도 그 스킬을 따른다.

# Step 6. 복습 모드 (`review`)
`review`는 당일 복습이 아니라 **다음 복습일이 된 문항만** 다시 시험 보는 모드다. 기본은 PDF 시험지로 만든다(사용자가 손글씨를 선호한다). `review chat`이면 대화형으로 한다.

0. **오답노트 옮기기**: 학습 로그에 `내 한 줄`이 `(정리 전)`인 행이 있으면, 해당 날짜의 `<STUDY>/오답/... 오답노트.pdf`를 읽는다. 필기를 문항별로 옮겨 적어 보여 주고 확인받은 뒤 `내 한 줄`에 원문 그대로 채운다. 문항마다 맞은 부분과 빠진 부분을 1~2줄로 짚는다. 문장이 "헷갈렸다" 같은 감상이면 개념 문장으로 쓰는 게 효과가 크다고 한 번만 알린다. 사용자 문장은 고쳐 쓰지 않는다. 빠진 부분이 크면 원인을 갱신할 수 있다(예: `개념 공백` → `오개념`). 아직 안 쓴 오답노트는 `(정리 전)`으로 두고 넘어간다.
1. 학습 로그에서 **다음 복습일이 오늘 이하이고 졸업하지 않은 행**을 모은다. 없으면 "오늘 복습할 문제가 없다"고 알리고 끝낸다. 밀린 행도 함께 모은다.
2. 해당 행이 가리키는 노트와 원래 정답 키를 읽어 근거로 삼는다. 항목이 많으면 복습일이 오래된 순으로 8개까지만 낸다.
3. 복습 문제도 Step 2의 비율(실물 읽기·실무 판단 절반 이상)을 따른다. 이전 문제를 **그대로 다시 내지 않는다.** `몰랐던 것`의 개념을 다른 각도나 다른 유형으로 변형해서 낸다. 원인이 `오개념`인 행은 그 오개념을 정면으로 건드리는 문항(예: 같은 착각을 담은 오류 찾기)으로 낸다. `내 한 줄`에 빠진 부분이 있었다면 그 부분을 묻는다. `이력`에서 같은 개념이 세 번 이상 틀렸으면 문제를 더 내기보다 노트를 다시 읽거나 개념을 쪼개라고 알린다.
4. 시험지에는 질문만 넣는다. 이전 내 답이나 내 한 줄은 넣지 않는다.
5. PDF면 Step 7-A 형식으로 `<STUDY>/복습/YYYY-MM-DD 복습 시험지.pdf`를 만들고(`<STUDY>/시험`이 아니다. 폴더가 없으면 만든다), 정답 키 `<KEYS>/YYYY-MM-DD 복습.md`에는 문항마다 **원래 학습 로그 행(날짜, 문제)**을 함께 적어 둔다. 채점은 `/test grade`로 한다.
6. 채점은 Step 4와 같다. 채점 결과에 그 문항의 **이전 내 한 줄**을 함께 보여 줘서 지금 답과 비교하게 한다. 다시 틀린 문항은 복습 오답노트에 넣어 새로 정리하게 한다. 이때 오답노트 문항에 이전 한 줄을 함께 보여 줘서 무엇이 달라졌는지 비교하며 쓰게 한다.
7. 복습 채점은 새 행을 추가하지 않고 **원래 행을 갱신**한다(결과, 원인, 단계, 다음 복습일). `이력`에는 이번 결과를 덧붙이고, 새 한 줄은 기존 한 줄 뒤에 ` / `로 덧붙인다. `내 답`은 처음 답을 그대로 둔다.

| 결과 | 갱신 |
|---|---|
| 정답 | 단계를 1 올리고 그 단계의 간격만큼 다음 복습일을 잡는다. 5단계를 통과하면 `졸업`으로 표시하고 복습일을 비운다 |
| 부분 정답 | 단계는 유지하고 복습일을 1일 뒤로 잡는다 |
| 오답 | 단계 1로 되돌리고 복습일을 1일 뒤로 잡는다 |

# Step 7. PDF 모드 (손글씨로 풀기, 기본 모드)
대화창 대신 시험지 PDF에 손글씨로 풀고, 답안을 가져와 채점한다. 시험지는 `<STUDY>/시험` 폴더에 두어 어느 기기에서든 열어 필기할 수 있게 한다.

## 경로
- 시험지: `<STUDY>/시험/YYYY-MM-DD 노트이름 시험지.pdf`
- 정답 키: `<KEYS>/YYYY-MM-DD 노트이름.md` (시험 전에 정답이 눈에 띄지 않게 숨김 폴더를 권장한다)
- 답안: 마크업으로 필기하면 시험지 PDF 자체에 저장된다. 사용자가 별도로 `... 답안.pdf`를 저장했으면 그 파일을, 아니면 시험지 PDF를 답안으로 읽는다. 이미지로 줘도 된다.

## 7-A. 시험지 만들기
1. Step 1, 2에 따라 노트를 읽고 문제를 만든다. 단, 시험지에 **정답이나 힌트를 넣지 않는다.**
2. **정답 키**를 위 경로에 저장한다. 문제 번호, 유형, 문제 원문, 모범 답안 요점, 채점 포인트를 적는다.
3. 시험지 HTML을 스크래치패드에 만든다. 형식은 다음과 같다.
   - 제목 `시험지: 노트이름`, 문제 수, "노트를 보지 않고 풀기" (날짜는 파일 이름에만 넣고 본문에는 넣지 않는다)
   - 제목 아래 안내 한 줄: "확신이 없으면 답 옆에 ? 표시, 찾아봤다면 (참고함)이라고 적기"
   - 문제마다 `.q` 블록(`page-break-inside: avoid`)에 번호, 문제 문장, 답안칸(`.ans`). **유형 태그(설명하기, 오류 찾기 등)는 시험지에 표시하지 않는다.** 유형은 출제와 학습 로그에서만 쓴다.
   - 번호는 `1.`처럼 줄 맨 앞(왼쪽 여백)에 둔다. 채점 때 `cropq.swift`가 이 번호 위치로 문제를 잘라낸다.
   - **쪽 배치: 한 페이지를 위아래 반으로 나눠 페이지당 2문제만 넣는다.** 구현: 페이지마다 `<div class="page">`로 감싸고(`@page { margin:12mm 16mm }`, `.page { height:250mm; display:flex; flex-direction:column; page-break-after:always }`, 높이가 이보다 크면 빈 페이지가 끼므로 넘기지 않는다), 그 안에 문제 블록 두 개(`.q { flex:1 1 0; display:flex; flex-direction:column }`)를 넣는다. 문제 문장 아래 남는 공간 전체가 답안칸(`.ans { flex:1 }`)이 된다. 번호는 첫 문단 안에 `<b>1.</b>`로 넣는다(줄 맨 앞). 문제 수가 홀수라 마지막에 혼자 남는 문제는 그 페이지를 다 써도 된다. 제목과 안내는 첫 페이지 맨 위에 짧게 두고, 그만큼 첫 페이지의 두 칸을 조금 줄인다.
   - 문제와 자료(출력, 인용)만으로 반 칸의 절반을 넘어 답 쓸 공간이 부족하면, 그 문제는 **한 페이지 전체**를 쓴다(높이 약 245mm). 이때도 한 페이지에 3문제 이상 넣지 않는다. 실습 과제는 항상 한 페이지 전체를 쓴다.
   - 실물 읽기의 출력은 `<pre>`(Menlo 8.5~9pt, 옅은 회색 배경)로 넣고, 길면 필요한 줄만 남기고 생략한 곳에 `...`를 쓴다.
   - 폰트는 `"Apple SD Gothic Neo"`, 본문 11pt, 오류 찾기 문제는 틀린 문장을 본문에 인용한다.
4. PDF로 변환한다. 스킬 폴더의 스크립트를 쓴다. (macOS 기본 WebKit 사용, 설치 불필요)
   ```bash
   swift "<SKILL>/scripts/html2pdf.swift" <시험지.html> "<시험지.pdf>"
   ```
   `CFURL...` 경고는 무시해도 된다. 변환 후 PDF를 읽어 한글, 쪽 나눔, 답안칸이 정상인지 확인한다. 저장 경로의 `<STUDY>/시험` 폴더가 없으면 먼저 만든다.
5. 사용자에게 파일 위치(`<STUDY>/시험`)만 짧게 알린다. 특정 기기의 사용법은 설명하지 않는다. 다 풀면 `/test grade`를 하도록 안내한다.

## 7-B. 답안 채점 (`grade`)
1. 정답 키와 원 노트를 읽는다.
2. 답안 PDF(또는 이미지)를 읽는다. PDF는 `pages`로 나눠서 본다.
3. 손글씨는 **읽은 내용을 문제별로 먼저 옮겨 적어 사용자에게 보여 주고, 맞는지 확인받은 뒤 채점한다.** 이때 `?`와 `(참고함)` 표시도 함께 옮겨 적는다. (처리 방법은 "답안 표시 처리" 참고) 알아보기 어려운 글자는 추측하지 말고 "이렇게 읽었는데 맞나요"라고 묻는다.
4. Step 4에 따라 문제별로 채점하고 모든 문항의 해설을 대화창에 보여 준다.
5. **문제마다 바로 아래에 해설을 넣은 채점 시험지를 만든다**(아래 형식). 태블릿 마크업 필기(예: iPad 마크업)는 페이지마다 한 장의 이미지(stamp)로 저장될 수 있으므로, 문제 영역을 필기째 잘라 이미지로 만들고 그 아래에 해설을 붙여 PDF를 다시 만든다.
   ```bash
   # 문제 번호("1.", "2." ...) 위치로 문제+필기 영역을 잘라 q1.png ... 로 저장 (아래 빈 공간은 자동으로 잘라냄)
   # 마지막 인자는 채점 표시: 문제 순서대로 O(정답) / T(부분 정답, 세모) / X(오답)를 쉼표로 (예: O,T,X,O,X,X)
   # 번호 위에 빨간 ○ △ ✕ 가 그려진다. `?` 정답은 일정상 부분 정답이지만 표시는 O로 한다.
   swift "<SKILL>/scripts/cropq.swift" "<시험지.pdf>" <스크래치패드>/crops <문제 수> <원래 시험지 페이지 수> "O,T,X,..."
   # crops/qN.png 를 <img>로 넣은 채점 HTML을 같은 스크래치패드 폴더에 만들고 변환
   swift "<SKILL>/scripts/html2pdf.swift" <스크래치패드>/graded.html <스크래치패드>/graded.pdf
   ```
   - 만든 PDF를 읽어 문제마다 필기와 해설이 맞게 붙었는지 확인한다.
   - 확인되면 원래 시험지를 그 시험지가 있는 폴더의 `.원본/`(`<STUDY>/시험/.원본/` 또는 `<STUDY>/복습/.원본/`, 숨김 폴더)에 복사해 두고, 같은 이름으로 채점 시험지를 덮어쓴다. 원본은 필기를 다시 고칠 수 있는 파일이다.
   - 이미 채점된 시험지(제목이 `채점:`)는 다시 만들지 않는다.
6. Step 5에 따라 결과 요약을 주고 학습 로그에 기록한다(오답노트 문항의 `내 한 줄`은 `(정리 전)`).
7. 헷갈림·모름 문항이 있으면 **오답노트 PDF**를 만든다(아래 형식). 단순 사실과 확신 정답은 넣지 않는다.
8. 손글씨 인식이 끝까지 불확실한 문제는 "판독 불가"로 표시하고 점수에서 제외한다.

### 채점 시험지 형식
- 반 페이지 배치는 적용하지 않는다. 문항 블록(필기 이미지 + 해설 + 질문·내 이해 칸)을 `page-break-inside: avoid`로 이어 붙여, 대개 한 페이지에 한 문항이 들어가는 지금 배치를 유지한다(사용자 선호).
- 시험지와 같은 스타일. 제목 `채점: 노트이름`, 점수 한 줄(정답 N / 전체, 부분 정답 N개)과 "해설을 읽고 이해한 뒤, 이 파일을 닫고 오답노트를 쓰기".
- 문항마다 `.q` 블록(`page-break-inside: avoid`)에 `<img src="crops/qN.png" style="width:100%">`(문제와 내 필기), 그 바로 아래 해설 상자(왼쪽 회색 선, 옅은 배경)를 둔다.
- 해설 상자 맨 위에는 `해설`이라는 회색 라벨만 둔다. 정답 여부는 번호 위의 ○ △ ✕로 알 수 있으므로 판정 글자는 넣지 않는다. 그 아래 Step 4의 해설 항목(모범 답안 요점, 내 답과의 차이, 왜 그렇게 생각하기 쉬운지, 노트에서 볼 곳)을 넣는다.
- 채점 뒤에 사용자가 더 쓴 필기가 있으면 점수에는 넣지 않고, 해설에 "채점 후 쓴 답에 대해" 한 줄로 짚는다.
- 각 `.q` 블록 맨 앞에 숨김 표시를 넣는다: `.q { position: relative; }`, `.mk { position: absolute; top: 0; left: 0; color: #fff; font-size: 2pt; line-height: 2pt; }`, `<span class="mk">@Q1@</span>`. `check` 단계에서 이 표시로 문항 블록을 잘라낸다.
- 해설 상자 바로 아래에 **"질문·내 이해" 빈칸**(테두리 점선, 약 80pt, 왼쪽 위에 회색 작은 글씨로 `질문 · 내 이해`)을 둔다. 사용자가 해설을 읽으며 모르는 표현이나 자기가 이해한 내용을 필기하는 곳이고, `/test check`가 읽는다.

### 오답노트 PDF 형식
- 경로: `<STUDY>/오답/YYYY-MM-DD 노트이름 오답노트.pdf` (복습이면 `YYYY-MM-DD 복습 오답노트.pdf`). Step 7-A와 같은 HTML → PDF 방식으로 만든다.
- 제목 `오답노트: 노트이름`, 안내 한 줄: "해설을 읽고 시험지를 닫은 뒤 자기 말로 쓰기. 막히면 막힌 데까지만 쓰기. 분량은 자유."
- 문항마다 번호, 원래 문제(한 줄), 내 답(원문), 판정, 빈칸 틀, 답안칸(약 150pt). **정답과 해설은 넣지 않는다.** 이 파일을 쓰는 동안 답이 눈에 들어오지 않게 하기 위해서다.

| 종류 | 빈칸 틀 |
|---|---|
| 헷갈림 | "나는 ___라고 생각했다 → 실제로는 ___ → 왜냐하면 ___" |
| 모름 | "___는 ___이다. 그래서 ___" (정의 + 그 결과로 생기는 일) |

- 사용자에게 시험지의 문제마다 해설이 들어갔다는 것과 오답노트 위치를 알린다. 해설을 읽으며 모르는 표현이나 내가 이해한 것을 "질문·내 이해" 칸에 적었다면 `/test check`로 먼저 확인받고, 그다음 **시험지를 닫은 뒤** 오답노트를 쓰라고 안내한다. 보면서 옮겨 적으면 다시 읽기와 효과가 비슷하다는 점을 한 줄로 덧붙인다. 다 쓴 오답노트는 다음 `/test review` 때 읽어서 학습 로그에 옮긴다고 알린다.

## 7-C. 해설 확인 (`check`)
해설을 읽는 단계에서 이해를 확인한다. 잘못 이해한 채로 오답노트를 쓰면 틀린 내용을 외우게 되므로, 오답노트를 쓰기 **전에** 한다.

1. 채점 시험지 PDF, 같은 날짜의 정답 키, 원 노트를 읽는다.
2. 문항별 "질문·내 이해" 칸의 필기(해설 상자 주변의 밑줄, 동그라미, 물음표 표시 포함)를 표로 옮겨 적어 보여 준다. 채점이 아니므로 확인을 기다리지 않고 바로 답하되, 판독이 불확실한 부분만 표시하고 "다르면 알려 달라"고 한다. 필기가 없는 문항은 건너뛴다.
   - 다른 기기에서 한 필기는 동기화로 넘어오는 데 시간이 걸린다. 파일 수정 시각이 채점 시각과 같고 필기가 없으면, 몇 초 뒤 다시 확인한다.
   - 필기를 읽는 동안에는 채점 시험지를 바꾸지 않는다. 사용자가 다른 기기에서 열어 필기 중일 수 있고, 동기화가 겹치면 필기가 사라질 수 있다. 바꾸는 것은 5번에서 한 번만 한다.
3. 문항마다 답한다.
   - **모르는 표현·질문**: 짧고 쉽게 설명한다. 이 문제의 맥락에 맞는 예를 하나 든다.
   - **내 이해**: `맞음 / 일부 틀림 / 틀림`으로 판정하고, 틀린 부분이 있으면 어디가 왜 틀렸는지와 바르게 고친 문장을 준다. 사용자 문장 자체는 고쳐 쓰지 않는다.
4. 질문한 표현과 **틀린 이해**는 `study-log` 스킬에 따라 학습 로그에 기록한다(질문은 "개념 질문", 틀린 이해는 "이해 확인" 행). 맞은 이해는 기록하지 않는다.
5. **답변을 채점 시험지에도 적는다.** 사용자가 필기를 마치고 `check`를 부른 것이므로 이때는 파일을 바꿔도 된다. 단, 바꾸기 직전에 파일 수정 시각이 읽은 시점과 같은지 확인하고, 다르면 다시 읽는다.
   - 원래 파일을 그 시험지가 있는 폴더의 `.원본/YYYY-MM-DD 노트이름 채점(check 전).pdf`로 복사해 둔다.
   - 숨김 표시가 있으면 문항 단위로 자른다: `swift "<SKILL>/scripts/cropq.swift" "<채점 시험지.pdf>" <스크래치패드>/chk <문제 수> 99 "" "@Q"`. 새 HTML에 문항마다 블록 이미지(`chk/qN.png`, 필기 포함), 그 바로 아래 **파란 답변 상자**(왼쪽 파란 선, 옅은 파란 배경, 라벨 `질문 답변` 또는 `내 이해 확인 · 맞음/일부 틀림/틀림`, 회색 작은 글씨로 내 질문·내 이해 원문, 그 아래 답변)를 넣는다. 필기가 없는 문항은 블록 이미지만 넣는다.
   - 숨김 표시가 없는 예전 채점 시험지는 페이지 단위로 한다. `swift "<SKILL>/scripts/renderpages.swift" "<채점 시험지.pdf>" <스크래치패드>/pages <페이지 수>`로 페이지마다 필기째 이미지로 만들고, 그 페이지에 있는 문항들의 답변 상자를 페이지 이미지 바로 아래에 넣는다.
   - HTML → PDF로 만들어 읽어 본 뒤, 같은 이름으로 덮어쓴다. 새 파일에도 숨김 표시를 그대로 넣어 두어 `check`를 다시 할 수 있게 한다.
6. 마무리로 "이제 시험지를 닫고 오답노트를 쓰라"고 안내한다. 확인한 내용을 오답노트에 그대로 옮겨 적지 말고 기억에서 꺼내 쓰라고 한 줄 덧붙인다.
7. `check`는 선택이다. 질문이나 이해 필기가 하나도 없으면 "확인할 필기가 없다"고 알리고 끝낸다.

# Step 8. 사전 테스트 모드 (`pre`)
아직 읽지 않은 노트로 미리 시험을 본다. 틀려도 정답을 바로 공부하면 그냥 읽는 것보다 학습이 잘 된다. 목적이 "측정"이 아니라 "뒤에 읽을 내용에 대한 질문 만들기"이므로 복습 시험과 다르게 다룬다.

1. 문제는 3~5개, 노트의 **핵심 개념**만 묻는다. 세부 사항이나 여러 개념을 엮은 문항은 내지 않는다.
2. 진행과 채점은 Step 3, 4와 같다. 다만 "모르겠다"는 바로 받아들이고 정답과 피드백으로 넘어간다(힌트 단계 생략). 틀려도 괜찮다고 시작할 때 한 줄로 알린다.
3. 결과 요약에 점수를 크게 강조하지 않는다. 대신 "노트를 읽을 때 특히 볼 부분"을 문항별로 짚는다.
4. **학습 로그에 기록하지 않는다.**
5. 마무리로 지금 노트를 읽으라고 안내하고, 하루 이상 지난 뒤 `/test <노트>`로 복습 시험을 보라고 권한다.
6. 시험지 제목을 `사전 테스트: 노트이름`으로 하고, 정답 키 파일 이름 끝에 ` (사전)`을 붙인다.

# 주의
- 응답은 한국어로 하고, 부연 설명에 em-dash(—)를 쓰지 않는다. 괄호나 줄 분리를 쓴다.
- 쓰기는 학습 로그, PDF 모드의 `<KEYS>/`(정답 키), `<STUDY>/시험/`(시험지), `<STUDY>/복습/`(복습 시험지), `<STUDY>/학습 로그.md`, `<STUDY>/오답/`(오답노트 PDF)에만 한다. 시험 대상 노트가 틀린 것 같으면 알리기만 하고, 고치는 것은 사용자가 요청할 때 한다.
- 시험 중에는 노트 내용을 요약하거나 다시 설명해 주지 않는다. 사용자가 시험을 중단하고 설명을 요청하면 그때 응한다.
