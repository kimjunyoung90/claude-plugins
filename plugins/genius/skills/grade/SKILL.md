모든 문항에 해설을 주는 채점 스킬이다. 맞힌 문항도 해설을 보면 제대로 알고 맞힌 것인지, 어쩌다 맞힌 것인지 가려진다.

# 경로와 공용 규칙
`<SKILL>`은 이 스킬의 기본 폴더, `<ROOT>`는 플러그인 루트(`<SKILL>/../..`)다.
- 경로 설정과 학습 로그 형식: `<ROOT>/references/learning-log-format.md`. **설정 파일이 없으면** 채점하지 말고 `/genius:setup`을 먼저 실행하라고 안내한다.
- 채점 기준(판정, 해설, 답안 표시, 결과 요약, 학습 로그 기록·갱신): `<ROOT>/references/grading.md`
- 시험지·정답 키 경로: `<ROOT>/references/exam-sheet.md`

# 1. 답안 찾기
- 인자로 파일을 주면 그 파일을 쓴다.
- 없으면 `<STUDY>/시험`과 `<STUDY>/복습`을 함께 보고 가장 최근에 수정된 `... 시험지.pdf`(또는 `... 답안.pdf`)를 쓴다.
- 이미 채점된 시험지(제목이 `해설지:`, 예전 파일은 `채점:`)는 다시 채점하지 않는다.
- 파일 이름으로 새 시험인지 복습 시험인지 정한다(`<STUDY>/복습/...`이면 복습). 학습 로그를 쓰는 방법이 다르다(`grading.md`의 "학습 로그 기록"과 "학습 로그 갱신").

# 2. 채점
1. 정답 키와 원 노트를 읽는다. 복습이면 정답 키에 적힌 원래 학습 로그 행도 읽는다.
2. 답안 PDF(또는 이미지)를 읽는다. PDF는 `pages`로 나눠서 본다.
3. 손글씨는 **읽은 내용을 문제별로 먼저 옮겨 적어 사용자에게 보여 주고, 맞는지 확인받은 뒤 채점한다.** 이때 `?`와 `(참고함)` 표시도 함께 옮겨 적는다. 알아보기 어려운 글자는 추측하지 말고 "이렇게 읽었는데 맞나요"라고 묻는다.
4. `grading.md`에 따라 문제별로 채점하고 모든 문항의 해설을 대화창에 보여 준다.
5. 손글씨 인식이 끝까지 불확실한 문제는 "판독 불가"로 표시하고 점수에서 제외한다.

# 3. 해설지 만들기
**문제마다 바로 아래에 해설을 넣은 해설지를 만든다.** 태블릿 마크업 필기(예: iPad 마크업)는 페이지마다 한 장의 이미지(stamp)로 저장될 수 있으므로, 문제 영역을 필기째 잘라 이미지로 만들고 그 아래에 해설을 붙여 PDF를 다시 만든다.
```bash
# 문제 번호("1.", "2." ...) 위치로 문제+필기 영역을 잘라 q1.png ... 로 저장 (아래 빈 공간은 자동으로 잘라냄)
# 마지막 인자는 채점 표시: 문제 순서대로 O(정답) / T(부분 정답, 세모) / X(오답)를 쉼표로 (예: O,T,X,O,X,X)
# 번호 위에 빨간 ○ △ ✕ 가 그려진다. `?` 정답은 일정상 부분 정답이지만 표시는 O로 한다.
swift "<ROOT>/scripts/cropq.swift" "<시험지.pdf>" <스크래치패드>/crops <문제 수> <원래 시험지 페이지 수> "O,T,X,..."
# crops/qN.png 를 <img>로 넣은 채점 HTML을 같은 스크래치패드 폴더에 만들고 변환
swift "<ROOT>/scripts/html2pdf.swift" <스크래치패드>/graded.html <스크래치패드>/graded.pdf
```
- 만든 PDF를 읽어 문제마다 필기와 해설이 맞게 붙었는지 확인한다.
- 확인되면 원래 시험지를 그 시험지가 있는 폴더의 `.원본/`(`<STUDY>/시험/.원본/` 또는 `<STUDY>/복습/.원본/`, 숨김 폴더)에 복사해 두고, 같은 이름으로 해설지를 덮어쓴다. 원본은 필기를 다시 고칠 수 있는 파일이다.

형식:
- 반 페이지 배치는 적용하지 않는다. 문항 블록(필기 이미지 + 해설 + 질문·내 이해 칸)을 `page-break-inside: avoid`로 이어 붙여, 대개 한 페이지에 한 문항이 들어가는 지금 배치를 유지한다(사용자 선호).
- 시험지와 같은 스타일. 제목 `해설지: 노트이름`, 점수 한 줄(정답 N / 전체, 부분 정답 N개)과 "해설을 읽고 이해한 뒤, 이 파일을 닫고 오답노트를 쓰기".
- 문항마다 `.q` 블록(`page-break-inside: avoid`)에 `<img src="crops/qN.png" style="width:100%">`(문제와 내 필기), 그 바로 아래 해설 상자(왼쪽 회색 선, 옅은 배경)를 둔다.
- 해설 상자 맨 위에는 `해설`이라는 회색 라벨만 둔다. 정답 여부는 번호 위의 ○ △ ✕로 알 수 있으므로 판정 글자는 넣지 않는다. 그 아래 `grading.md`의 해설 항목(모범 답안 요점, 내 답과의 차이, 왜 그렇게 생각하기 쉬운지, 노트에서 볼 곳)을 넣는다. 복습이면 이전 내 한 줄도 넣는다.
- 채점 뒤에 사용자가 더 쓴 필기가 있으면 점수에는 넣지 않고, 해설에 "채점 후 쓴 답에 대해" 한 줄로 짚는다.
- 각 `.q` 블록 맨 앞에 숨김 표시를 넣는다: `.q { position: relative; }`, `.mk { position: absolute; top: 0; left: 0; color: #fff; font-size: 2pt; line-height: 2pt; }`, `<span class="mk">@Q1@</span>`. `/genius:note`가 이 표시로 문항 블록을 잘라낸다.
- 해설 상자 바로 아래에 **"질문·내 이해" 빈칸**(테두리 점선, 약 80pt, 왼쪽 위에 회색 작은 글씨로 `질문 · 내 이해`)을 둔다. 사용자가 해설을 읽으며 모르는 표현이나 자기가 이해한 내용을 필기하는 곳이고, `/genius:note`가 읽는다.

# 4. 결과 요약과 학습 로그
`grading.md`에 따라 결과 요약을 주고 학습 로그에 기록한다. 새 시험이면 모든 문항을 행으로 넣고, 복습이면 원래 행을 갱신한다. 오답노트에 넣을 문항(헷갈림·모름)은 `내 한 줄`을 `(정리 전)`으로 둔다. `/genius:note`가 이 표시로 오답노트 문항을 고른다.

# 5. 마무리 안내
- 문제마다 해설이 들어갔다는 것을 알린다.
- 해설을 읽으며 모르는 표현이나 내가 이해한 것을 "질문·내 이해" 칸에 적은 뒤 `/genius:note`를 하라고 안내한다. note가 필기를 확인하고 오답노트를 만든다. 적은 게 없어도 `/genius:note`로 오답노트를 받는다.

# 주의
- 응답은 한국어로 하고, 부연 설명에 em-dash(—)를 쓰지 않는다.
- 쓰기는 `<STUDY>/시험/`, `<STUDY>/복습/`(해설지와 `.원본/`), `<STUDY>/학습 로그.md`에만 한다.
