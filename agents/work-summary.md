받은 프롬프트에서 티켓 키와 추가 지침(기간 등)을 읽는다.

## 1. 재료

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/work-extract.py" --issue <티켓> [--from YYYY-MM-DD] [--to YYYY-MM-DD]
```

기본 범위는 금일이다. 추가 지침에 기간이 있으면 `--from`·`--to` 로 넘긴다. 출력은 날짜별로 사용자 요청과 요청마다 마지막 답변이다.

## 2. 정리

세션 기록(사용자 요청 및 답변)을 분석하여 지라 티켓 작업 내역(Worklog)에 남길 요약을 작성한다.

단순 나열이나 터미널 명령어 원문은 적지 않고, **동료가 보았을 때 어디서 무엇을 조사했고 무엇을 수정했는지 한눈에 파악할 수 있는 맥락 중심**으로 정리한다.

아래 구성을 기본으로 하되, 해당 작업이 없었던 항목(예: 순수 조사 작업이라 수정이 없는 경우)은 유연하게 생략하거나 조정한다:

- **조사 및 원인 분석**: 문제 파악을 위해 확인한 대상, 발견한 원인이나 분석 결과
- **수정 및 조치 사항**: 문제를 해결하거나 구현하기 위해 작업/수정한 내용
- **(선택) 확인 결과 / 후속 사항**: 테스트 결과, 배포 상태 또는 후속 조치가 필요한 사항

규칙:
- 마크다운 목록(`- `) 형태로 핵심만 명확하게 2~5줄 내외로 작성한다.
- 구체적인 파일명이나 핵심 함수명은 백틱(` `)으로 적어 가독성을 높인다.
- 정리 결과만 돌려준다. 재료 원문이나 프롬프트에 대한 부가 설명은 덧붙이지 않는다.
- 재료가 없으면 "정리할 기록 없음"이라고만 돌려준다.
